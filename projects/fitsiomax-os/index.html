01Project Overview

Fitsiomax OS is an ERP-style business management platform designed to support operational workflows, role-based access, lead management, appointment coordination, physiotherapy operations, and payment tracking.

My work involves developing, testing, improving, and maintaining the platform while working across product requirements, interface design, business logic, and software quality.

02Business Problem

A service business moves every customer through several stages — first enquiry, follow-up, appointment, consultation, treatment, and payment. When those stages live in separate places, it becomes hard to see where each lead stands, who owns the next step, and which payments are still outstanding.

Different teams also need different views of the same information: business development, pre-sales, branch administration, and clinical staff each work on their own part of the journey.

03Project Goals

  1. One platform for the whole journeyBring leads, appointments, consultations, and collections into a single connected workflow.
  2. The right view for each roleGive every role a dashboard and access level that matches its responsibilities.
  3. Clear status at every stageMake it obvious where a lead or appointment stands and what needs to happen next.
  4. Visibility into paymentsTrack consultation and session collections, pending amounts, and payment schedules.
  5. Reliable, usable softwareKeep the product dependable through continuous testing and interface refinement — on desktop and mobile.

06Technical Implementation

Fitsiomax OS is a web application with a React front end and a Python / FastAPI back end, backed by MongoDB.

The interface is built from reusable components styled with Tailwind CSS and accessible Radix UI primitives. Forms use React Hook Form with Zod validation, dashboards use Recharts, and navigation between role-based views uses React Router.

This is a private product. Internal architecture, data models, endpoints, and security details are intentionally not published.

07Development Challenges

Many roles, one product

Each role needs its own dashboard and permissions, while the underlying workflow has to stay consistent for everyone.

Multi-stage workflows

Leads move through follow-ups, appointments, consultations, and payments — every transition has to keep the record accurate.

Dense data on small screens

Dashboards, forms, and status views need to stay readable and usable on mobile, not just on desktop.

Changes ripple

A fix in one workflow can affect another, which makes regression testing an essential part of every change.

08Testing Approach

  1. Functional testingCheck each feature against its requirement and expected behavior.
  2. Role-based workflow validationWalk through the same workflow as different roles to confirm each sees and can do the right things.
  3. UI testingVerify layouts, forms, popups, and status indicators across screen sizes.
  4. Defect identification & reportingDocument issues with clear steps to reproduce, expected result, and actual result.
  5. Regression testingRe-check related workflows after fixes and changes.
